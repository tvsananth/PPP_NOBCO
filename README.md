# Benchmarking for PPP : Non-linear Objective Binary Constrained Optimization (NOBCO)

## Description

This repository contains the software to solve the First Responder Network Design Problem (FRNDP) using the GAGA method developed in https://pubsonline.informs.org/doi/abs/10.1287/ijoc.2024.0574 and the Branch-and-Bound algorithm, which is the cSOA for this problem. We also provide the following:
1. Data instances generated for benchmarking.
2. Scripts to run GAGA and Branch-and-Bound.
3. Statistical analysis scripts to generate the Time-to-solution (TTS), Energy-to-solution (ETS) metrics and also to obtain metrics per batch. 


## Code
The code for GAGA and Branch-and-Bound is in the *src* directory. This is divided into 3 subdirectories: 
1. *code_paths_generation*: Path generation for benchmarking instances
2. *code_random*: To carry out Graver augmentation
3. *code_bnb*: Branch-and-Bound code  

## Compliation

Please compile the code in *src/code_random* and *src/code_bnb* directories using the Makefile. 
```
make
```

## Instances

The instances can be found in the *data/instances/random_instances* folder. We have 2 batches, each of 10 instances
1. nodes_10_0.75_*.csv: instances with n=10 nodes and edge density, p=0.75 (~ 50 variable size problems)
2. nodes_20_0.75_*.csv: instances with n=20 nodes and edge density, p=0.75 (~ 200 variable size problems for predictive benchmarking)

#### Generator

The Python scripts to generate instances can be found in the *generator* directory. First, use generator.py to generate instances and then run generator_reorder.py on the generated instances.
 
## Running

The scripts to run the GAGA and cSOA methods are in the directory *job_scripts*. 

### GAGA

To run GAGA, use the *run_gaga.sh* script along with arguments specifying the instance node size, edge density, ID of the instance, and ID of the run (100 runs per each instance). An example is provided in the *job_gaga.sh* script.

### D-GAGA

For predictive benchmarking, we developed D-GAGA (GAGA with decomposition) to solve 200 variable size problems. We tested using a) Hierarchical Decomposition (HD) and Alternating Minimization (AM) methods. 

To run D-GAGA, use the *run_dgaga.sh* script along with arguments specifying the instance node size, edge density, ID of the instance, decomposition method, and ID of the run (100 runs per each instance). An example is provided in the *job_dgaga.sh* script.


### Branch-and-Bound (cSOA)

To run Branch-and-Bound, use the *run_bnb.sh* script along with arguments specifying the instance node size, edge density, ID of the instance, and the run time of the algorithm. An example is provided in the *job_bnb.sh* script. 

## Notes on Running and Analysis

### Running
1. GAGA/D-GAGA is run on each instance 100 times. 
2. GAGA is used to solve instances with n=10 nodes and edge density, p=0.75 (~ 50 variable size problems)
3. D-GAGA is run on instances with n=20 nodes and edge density, p=0.75 (~ 200 variable size problems) using Hierarchical Decomposition and Alternating Minimization techniques.
4. In total, 3000 simulation experiments were performed (1000 using GAGA and 2000 with D-GAGA).
5. cSOA (Branch-and-Bound) is run for ~10x times the maximum time of GAGA/D-GAGA in a given batch. The run time of cSOA is denoted by T<sub>cSOA</sub>. We used T<sub>cSOA</sub>=4320 seconds for 50 variable size problems and T<sub>cSOA</sub>=72000 seconds for 200 variable size problems. 

### Analysis

1. We use the notation, Obj<sub>GAGA/D-GAGA</sub> to denote the objective function obtained using GAGA/D-GAGA and Obj<sub>cSOA</sub> for the objective function obtained from Branch-and-Bound
2. The success fraction is defined as the percentage of runs (among the 100 for each instance) with Obj<sub>GAGA/D-GAGA</sub> < Obj<sub>cSOA</sub>.
3. The TTS/ETS metrics are calculated using the TTS-Q and TTS-R definitions. 
4. The confidence intervals for TTS-Q are obtained from Bootstrapping. For TTS-R, the Jeffreys interval is used. 
5. Finally, we calculate the following metrics per batch using TTS-Q:
	a) Mean and standard deviation of the logarithm of TTS and ETS across all instances in the batch.
	b) Cumulative density function (CDF) for TTS/ETS.
	c) 50% quantile, 75% quantile and 90% quantile for TTS/ETS along with an estimation of errors using bootstrap resampling of each instance. 

## Analysis scripts

The scripts to analyze the output data generated from GAGA, D-GAGA and Branch-and-Bound can be found in the *analysis_scripts* directory. 

1. JSON files containing the benchmarking data can be generated by running the *benchmark_files.sh* script. The generated JSON files are stored in the *results* directory.

2. Use the *metrics.sh* script to generate JSON files containing TTS/ETS data, computing metrics per batch and plots of CDF and quantiles per batch. The JSON files are stored in the *results* directory, and the plots can be found in the folder, *results/plots*.
